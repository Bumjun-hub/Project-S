# 프론트 회귀 검증

Node.js 22.6 이상이 필요합니다. 추가 테스트 라이브러리 설치 없이 Node 테스트 러너와 TypeScript 타입 제거 기능을 사용합니다.

```powershell
npm run test:unit
npx tsc --noEmit
npm run build
```

단위 테스트 8개는 토큰 만료/잘못된 토큰/SSR 안전성, 서버 이력 ID·시각·비교값 매핑, 페이지 경계,
세션 초기화 중 공개 상품 요청 유지와 사용자 전환 시 개인 캐시 제거를 확인합니다.
현재 브라우저 검증은 수동이며 자동 E2E 테스트가 구성된 것은 아닙니다.

## 브라우저 검증 시나리오 (2026-10-01 확인)

실제 계정이나 DB를 건드리지 않도록 별도 origin의 데모 서버에서 수행했습니다.
PowerShell 세션의 `NEXT_PUBLIC_DEMO_MODE=true`만 사용하며 `.env.local`을 변경하지 않습니다.
테스트를 끝내면 서버와 테스트 탭을 닫고, 일반 실행에서 데모 환경 변수를 제거하세요.

1. 비로그인 상태에서 `/products` 목록 조회가 가능함.
2. 상품의 핏 분석 선택 → 로그인 → 프로필 → 기준 옷 저장 → 처음 선택한 상품의 결과로 복귀함.
3. 결과에 부위별 비교 4개 모두 표시됨. 피드백 선택 후 분석 기록에서도 선택 상태가 유지됨.
4. 390px 모바일 화면에서 메뉴를 열어 Analysis History에 접근 가능함. Escape로 닫을 수 있음.
5. 로그아웃하면 `/history` 접근은 로그인으로 이동함.
6. 다른 데모 이메일로 로그인하면 이전 결과/기준 옷/프로필은 남지 않음.
7. 두 탭에서 계정을 전환하면 기존 탭의 메모리 상태도 초기화되고, 프로필 필드는 빈 값으로 표시됨.

실제 PostgreSQL 연결을 통한 브라우저 통합 검증 결과는 아래에 기록합니다.
백엔드의 H2 통합 테스트에서는 실제 인증·추천 저장·피드백 저장·이력 조회·다른 회원 접근 차단을 검증합니다.

## 실제 API 연동 검증 (2026-10-01)

로컬 PostgreSQL 마이그레이션 후 데모 모드를 끈 프로덕션 프론트 빌드와 실제 백엔드로 확인했습니다.
비로그인 첫 접속에서 공개 상품 요청이 세션 정리로 취소되는 결함을 발견하여,
개인 쿼리만 제거하고 공개 상품 쿼리는 유지하도록 수정하고 회귀 테스트를 추가했습니다.

상품 상세는 Next.js 서버에서 API를 호출하므로 `SERVER_API_BASE_URL`로 서버 전용 주소를 지정할 수 있습니다.
미설정 시 기존 `NEXT_PUBLIC_API_BASE_URL`을 사용합니다. 로컬 IPv4로만 백엔드를 실행한 경우
Node.js가 `localhost`를 `::1`로 해석할 수 있어 서버 전용 값은 `http://127.0.0.1:8080`을 사용합니다.
이 설정은 브라우저의 공개 API 주소와 분리되며 `.env.local`을 변경하지 않고 실행 환경 변수로도 지정할 수 있습니다.

실제 브라우저에서 확인한 흐름:

1. 비로그인 첫 상품 목록과 서버 렌더링 상품 상세가 정상 표시됨.
2. 상품에서 분석 시작 → 실제 JWT 로그인 → 프로필 → 기준 옷 저장 → 원래 상품 분석 결과로 복귀함.
3. 추천 결과의 비교값 4개가 실제 PostgreSQL에 저장됨.
4. `잘 맞아요` 피드백 저장 후 분석 기록을 새로고침해도 선택 상태가 유지됨.
5. 기록의 `결과 다시보기`에서 저장 당시 비교값 4개와 피드백이 복원됨.
6. 로그아웃 시 보호 화면은 로그인으로 이동함.

검증 전용 계정과 해당 계정의 데이터만 제거했고, 기존 회원 1명과 추천 이력 6건은
검증 전후 체크섬이 동일했습니다. 단위 테스트 8개 및 프로덕션 빌드도 통과했습니다.
